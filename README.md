# Capsule Host

期限付き共有アプリの共通ホスト。最初のDomain Kitは旅程。参加者はアカウント登録せず、権限付き共有リンクで利用します。
旅行の中の「チャットで直す」は、オーナー・編集者が自分の席に自分の Anthropic API キーを登録すれば、貼り付けなしで Host が直せます（鍵は席ごとのもので、ほかのメンバーや作成者は使えません）。作成者が自分の Anthropic API キーを登録すると、画面に希望を書くだけで Host が旅程を作れます（費用は鍵の持ち主の Anthropic 請求で、鍵は暗号化して保管し、画面には二度と表示しません）。
旅程は、しおりの画面で「作り方をコピー」して使い慣れたチャット（ChatGPTなど）に貼り、返ってきた答えをそのまま画面に貼り戻して作れます。前後に説明の文が混ざっていても構いません。おかしな点があれば、どの項目がなぜ不正かが日本語で出ます。作り方・貼り付け・保存は、**作成者としてパスキーでサインインしたブラウザだけ**に出ます（作成者は運用者が `bun aws/creator.ts enroll` で出す1回限りの登録リンクをスマホで開き、パスキーを作ってなります）。保存したら、その旅行のオーナーを選びます: この端末をオーナーにする（そのまま旅行が開く）か、オーナーリンクを受け取って別の端末・別の人に渡すか。作成者の権利では、誰の旅行も（自分が作った旅行も）読めません。CLI（IAM）からの発行も今までどおり使えます。作った後の旅行は、オーナーが「共有・管理」→「チャットで直す」で今の旅程をコピーしてチャットに直してもらい、答えを貼って、今の旅程との差分を見てから反映できます（直してほしいことを画面で書いてからコピーすれば、チャットに貼ってそのまま送れます。書かずにコピーしてチャットで頼んでも構いません）（大きな変更は旅行の題の入力が要り、1 つ前に戻せます。候補・相談も直せ、今ある候補・相談を変える・消すときは題の入力が要ります。思い出とチェックは消えません）。編集者も、画面上部の「チャットで直す」から同じ手順で予定・候補・相談・準備リスト・メモ・費用メモを直せます（題・日程・期限などの設定は今のまま残り、変えられるのはオーナーだけです）。画面上部の「旅を保存」では、どのメンバーも旅程のページを、ブラウザで開ける 1 つのファイルとして共有シート（「ファイルに保存」・LINE・メール）かダウンロードで残せます。旅程・準備・候補・費用メモ・メモ・思い出を Markdown のテキストでコピーしてメモアプリなどに残すこともできます。オーナー・編集者はそこから ZIP（旅行記の Markdown・データの控え・カレンダー・ブラウザで開けるページ）も保存でき、中身とスマホでの開き方が同じ画面に書いてあります。

旅程の画面は日ごとのタブで、その日の予定を「詳細」（時刻・状態・メモ・地図リンクのカード）と「リスト」（時刻とタイトルだけ、1 件 1 行）で切り替えて見られます。選んだ表示はそのブラウザが覚えます。オーナー・編集者は、どちらの表示でも予定の持ち手（⠿）をドラッグするか、持ち手にフォーカスして上下の矢印キーを押すと、同じ日の中の順番を入れ替えられます。動かした予定の開始時刻は、置いた位置の前後の予定に合うように Host が書き換え（前の予定が終わる時刻、終了時刻が無ければ前の予定の 1 時間後など。前後の間に収まっていればそのまま）、変えたときは画面に「〇〇を 10:30 ごろ に変えました」と出ます。時刻の無い予定も、動かすとその位置の時刻が付きます。Host が決めた時刻は「仮置き」で、画面と書き出しでは「10:30 ごろ」と表します。「編集」の開始時刻は必須で、「時刻は仮置き（決定ではない）」のチェックで仮置きかどうかを選べます（時刻を変えるとチェックは外れます）。時刻の無い予定を「編集」で開くと、その位置の仮置きの時刻が入っています。候補から旅程に足した予定は、その日の最後に仮置きの時刻で入ります。「編集」で時刻を変えた予定も、その時刻の合う位置へ移ります。別の日へ移すには「編集」で日付を変えます。予定には終了時刻（任意）も入れられ、「10:30 – 12:00」と出ます。開始時刻を変えると終了時刻も同じだけずれます。同じ日のそれより前の予定のうち最も遅い終了と、その予定の開始から、間の空き時間（「空き 45 分」）と重なり（「前の予定と重なっています」）が旅程に出ます。知らせるだけで、他の予定の時刻や順番は変えません。予定と予定の間（と最後）の「＋」から、その位置に予定を足せます。フォームには前の予定から決めた仮置きの時刻（前の予定の終了、終了が無ければ開始の 1 時間後）が入っていて、その時刻のまま保存するとその位置に入ります（時刻を打ち直したとき・日付を変えたときは、時刻の合う位置）。

招待リンクは席の引換券で、開いたブラウザが1席を取り、以後の権限はそのブラウザに保存されたCookieが持ちます（Cookieは持っている人なら誰でも使えるので、端末そのものには縛られません）。参加後にパスキー（Face ID・指紋）を登録しておくと（任意）、Cookieを消しても同じ席に戻れ、PCからもスマホのパスキー（QR）で同じメンバーとして入れます。1メンバー＝1ブラウザは変わらないので、戻った側が有効になり、直前まで使っていたブラウザは開けなくなります（そちらも同じパスキーで戻せます）。編集者は閲覧者の招待を出せ、自分が出した招待だけを交換・失効できます（オーナーは「共有・管理」で各招待を誰が出したかを見られ、どれでも失効できます）。機密度の高い旅行では、招待の発行時に「オーナーが確認コードで承認」を選べます（既定は自動で参加）。引き換えた人の画面に出る6桁のコードをLINEなどでオーナーに伝え、オーナーが「共有・管理」で照合して承認するまで旅程は開きません（拒否しても席は戻りません）。オーナーが招待の発行・交換・失効、共有の終了、完全削除、設定・期限の変更をするとき（編集者が招待を発行・交換・失効するときも）は、その前にこの席に登録したパスキーで本人確認します（5 分間有効。閲覧と予定の編集では聞きません）。パスキーの無い席では、その場で登録を求め、登録したことが本人確認になります。登録済みのパスキーを置き換える（「パスキーを登録し直す」）ときも今のパスキーで本人確認するので、Cookie だけでは差し替えられません。パスキーを失ったメンバーはオーナーに失効と再招待を、オーナーは旅行を発行した人に `aws/recover.ts` での差し替えを頼みます。パスキーの使えないブラウザ（アプリ内ブラウザなど）では Safari・Chrome で開き直してください。旅行の画面の下の「この端末からログアウト」で自分の登録を終えられ（作成者はトップの「サインアウト」）、30 日開かなかった端末の登録も失効します。どちらもパスキーがあれば「パスキーで戻る」で同じ席に戻れ、無ければオーナーの再招待が要ります（オーナー自身は旅行を発行した人の `aws/recover.ts`）。誰がどの条件で旅行を開けるか、Cookie の盗難・招待リンクの漏洩・端末の紛失・運用者の権限ごとの対策と残るリスクは、[設計文書の §2.4.1](docs/ephemeral-trip-capsule.md#241-誰がアクセスできるか脅威と残るリスク) にあります。パスキーを登録しても、有効な Cookie を持つ人の閲覧は防げないので、閲覧の漏れも許せない情報はカプセルに置かないでください。

オーナーは「共有・管理」の「招待とオーナーの履歴」で、旅行の作成（日時だけ）、招待の発行・交換・失効、席の引換、共有の終了、オーナー招待の差し替え（`aws/recover.ts`・作成者の作り直し・発行の再実行）を、日時・役割・リンク名・操作した人（メンバー名と端末。差し替えは「発行者」「作成者」）つきで新しい順に見られます。見られるのはオーナーだけで、リンクの秘密や Cookie は残しません。知らないうちに招待やオーナーが増えていないかを確かめ、失効や差し替えを頼むためのもので、防ぐものではありません: オーナーが 2 人いると、片方が相手のオーナー席を「交換」で失効させたり、旅行を完全に削除したりでき、締め出された側は履歴も開けません。

どの役割のメンバーも、旅程の見出しの「＋ 自分だけの予定」や各共有予定の後の「＋ 自分だけ」から、個人予定を入力・保存できます。共有予定を追加できるメンバーには「＋ 共有」も並び、追加前に共有範囲を区別できます。日記は「思い出」の「自分の日記」で日付を選び、本文を入力して保存します。思い出がページ一覧にない既存の旅行にも、画面側で標準の思い出タブを補います（保存済みの Spec は変更しません）。その場合、共有の思い出の投稿機能は有効にせず、自分の日記を利用できます。共有する「みんなの思い出」と個人の日記は別の節にあり、各一覧の上のフォームから登録・編集できます。予定はその日のみんなの予定の間に時刻で並び、「自分だけ」の印が付きます。同行者とオーナーには見えず、ZIP や「チャットで直す」にも入りません。Host の運用者にも読めません（ブラウザで暗号化し、Host には暗号文だけを置きます。鍵はその席のパスキーで包むので、書くにはパスキーが要ります）。題・本文・場所以外（日付・時刻・件数）は運用者に見えます。自分の分は「自分のメモを保存 ↓」で Markdown にして持ち出せます。

旅行期間中は、閲覧のみ以外のメンバーが足あとの地図のページ（Spec に地図のページが無い旅行では「足あと」のページ）の「ここにいる」を押すと、その時刻と場所（ブラウザが返した緯度経度と精度）が足あととして残ります。初回はブラウザが位置の許可を求め、許可が無い・位置が取れない・精度が 1 km より悪いときは残さずに理由を出します。足あとは閲覧のみを含むメンバー全員が同じページの地図と、その下の日ごと・時刻順の一覧で見られ、地図のリンクは新しいタブで開きます。地図を拡大・移動して見ている間に他のメンバーの足あとが届いても、見ている場所と拡大はそのまま。日・メンバーの絞り込みを変えると点の範囲に合わせ直します。旅程の予定に座標（チャットで旅程を作る・直すときに LLM が付けます）があれば、予定の印（足あとと見分けのつく四角）で同じ地図に重なり、「予定」「足あと」と日で切り替えられます。一覧の「消す」で消せるのは残した本人とオーナー・編集者です。1 旅行 1000 件、1 人 1 分に 1 回までです。メンバーが失効しても点は名前つきで残り、旅行の削除で一緒に消えます。足あとは暗号化しないので、Host の運用者には読めます（旅程と同じ）。「開いたときに足あとを残す」をオンにした端末では（既定はオフ、端末ごと）、旅行期間中に旅行のページを開いた時と画面に戻った時に、前の自分の足あとから 15 分以上たったか 300 m 以上動いていれば、足あとを 1 点残し、一覧に「自動」と出ます。位置の許可を求めるのはオンにした時だけです。位置を見張り続けることはせず、画面を閉じている間や裏にある間は残りません。

旅行が終わった後（振り返り・共有終了）に旅行を開くと、「旅の記録」が最初に出ます。日ごとに予定が並び、足あとのある予定には「予定 12:00 / 記録 13:02」のように、その予定の時間帯の最初の足あとの時刻が出ます。その日の最初の予定より前・予定の終了より後・同じ予定の最初の足あとから 2 km 以上離れた足あとは「予定になかったところ」として、時刻・だれの足あとか・地図リンクで予定の間に並びます。旅行中も「旅の記録」のタブで、それまでの足あとから同じように見られます。旅程は書き換えません。

このリポジトリはSwitchboardから独立してテスト・開発・AWS配置できます。Switchboardは生成した成果物と公開状態を管理する制御面で、Hostのビルド依存ではありません。

## How this repository works

This repository is a read-only copy of a private development repository: its `main` is that repository's `main` tree, sent here by a sync as one commit at a time, without the private history. Nothing is developed here.

- **Issue and pull request numbers** (`#N`) in files and commit messages refer to the private tracker and cannot be opened here.
- **Pull requests are not accepted.** A pull request opened here is answered with this policy and closed automatically.
- **Requests and bug reports** go to an Issue of the kind *Request* (the only Issue form here). A request is read and taken into the private backlog; the Issue is answered there and closed with the outcome.
- **Vulnerabilities** are reported privately through a GitHub Security Advisory: https://github.com/iunct-lab/capsule-host/security/advisories/new (see `SECURITY.md`). Not in a public Issue or Discussion.
- **Questions and discussion** go to Discussions: https://github.com/iunct-lab/capsule-host/discussions

## ローカル開発

bun 1.4.3 以上が要ります（型検査に `bun --check` を使います。古い bun では `bun run typecheck` が止まります）。

```sh
bun install --frozen-lockfile
bun run check
bun run dev
```

画面の並べ替え、「詳細 / リスト」の切り替え、終了時刻の編集と空き・重なりの表示、編集者の「チャットで直す」（反映と 1 つ前に戻す）は、`bun run dev` を立てたまま `bun run verify:ui` で確かめられます（手元の Chrome か Chromium をヘッドレスで動かします。追加の依存はありません。見つからなければ `CHROME_PATH` に実行ファイルを指定）。架空の旅行を作って終わったら消し、リンクも Cookie も表示しません。場面は 5 つの群に分かれ、`bun run verify:ui <群>` で 1 つの群だけを流せます（引数なしは下の順に全部で、通しで約 5 分。知らない名前なら使える群を出して何もせずに止まります）。群はそれぞれ自分の架空の旅行を作って、要る招待・パスキー・鍵の受け渡し・暗号化を自分で用意し、終わったら（落ちても）消し、通れば最後に `[<群>] <秒> s` を出します。秒数は手元の目安です。

| 群 | 中身 | 目安 |
|---|---|---|
| `plan` | owner の旅程（並べ替え・時刻・終了・「＋」・詳細 / リスト）、テーマのコントラスト、旅を保存、招待とオーナーの履歴、準備・費用メモ、候補・相談 | 約 20 秒 |
| `members` | 参加者の画面、足あと・旅の記録・旅の足あと（地図）、閲覧者の足あと、開いたときに足あとを残す、編集者（チャットで直す・共有・管理・位置の要素） | 約 2 分 |
| `seat` | 参加者のパスキーとログアウト、鍵の受け渡し、自分の予定と日記、閲覧者のチャットで直す | 約 20 秒 |
| `passkey` | owner のパスキー（PRF の無いパスキー、5 分の後の登録し直し、パスキーで戻る）と画面からの削除 | 約 5 秒 |
| `sealed` | 暗号化した旅行（描画・旅を保存・足あと・招待とメンバー・チャットで直す・ここで直す・削除）、平文の旅行を移す、鍵を替える、owner の交換 | 約 2 分半 |

新しい場面はどれかの群に入れ、前の群が作った状態に頼らず、要る状態はその群の用意（`openTrip()` と `joinAs()`、`src/verify-ui.ts`）とその群の中の場面で作ります。

待つ相手（パスキーの確認の 5 分・1 分ごとの数え直し・足あとの 1 分）は Host の時計なので、verify:ui はループバックの `bun run dev` だけにある `POST /dev/clock` で時計を進めて待たずに進みます（進めた時計は `bun run dev` を立て直すまで進んだまま）。最後に同時に開いたページの最大を出します。`bun run check` と CI には入っていません。

`http://localhost:47840` を開きます（`127.0.0.1` ではなく `localhost`。ブラウザはIPアドレスをパスキーのRP IDとして受け付けないため、既定のOriginをこちらにしています）。この変更より前に作ったローカル開発データがある場合、cookieも招待リンクも `127.0.0.1` に紐づいているので `localhost` では開けません。`CAPSULE_ORIGIN=http://127.0.0.1:47840 bun run dev` で従来どおり使うか、架空データなので `CAPSULE_DATA_DIR` のディレクトリを消して作り直してください。別端末の `bun run verify:http` は権限・競合・出力をHTTP越しに検査し、作成した架空カプセルを削除します。実旅行はテストに使いません。

開発データの既定保存先は `~/.local/share/capsule-host/dev/`。`CAPSULE_DATA_DIR` で変更可能です。ソースリポジトリ内へ保存しません。ローカルもAWSも、認可・ライフサイクル・操作の適用は同じ `src/cloud-host.ts` を通ります。違うのは保存先（ローカルは `src/local-d1.ts` のSQLite、本番は `src/aws-store.ts` のDynamoDB）、その手前（CloudFront・Lambda Web Functions の OAC・IAM・参加登録の地域制限）、そして `src/main.ts` だけにあるローカル用の入口（静的ファイル、`/health`、preview、ループバックのときだけ画面から発行できること）です。違う部分はローカルでは確かめられないので、認可・保存・削除の変更はAWS devでも検証します。発行の上限（1分に5件、同時に保持できる旅行は10件）はローカルにも同じくかかります。作成者の鍵で旅程を生成する部分は `src/assist.ts` と `src/cloud-host.ts` の `/v1/assist` です。作成者が登録する Anthropic API キーは、`src/key-store.ts` で封じてから保存します（ローカルはSQLite、AWSは `src/aws-key-store.ts` のParameter Store）。

足あとの地図の背景（道路・地名・海岸線）は、開発データの置き場の `map/` に置いた地図データ（`japan.pmtiles` と `world.pmtiles`、既定なら `~/.local/share/capsule-host/dev/map/`）から `bun run dev` が出します。地図データはリポジトリに入れません。作り方は `pmtiles extract`（[設計メモ](docs/design/footprint-basemap.md)）で、手元では福岡周辺など小さな範囲を切り出せば足ります。無くても足あとの点と線は出ます（背景が無地になるだけ）。地図の部品（`map.js`・`maplibre-worker.mjs`・`map.css`）は足あとの地図を開いたときにだけ読み込まれます。

Hostを1実装にまとめる前のローカル開発データ（同じ `capsule.sqlite` にある旧テーブル）は読まれず、期限が来ても掃除されません。架空データなので、`bun run dev` を止めて `CAPSULE_DATA_DIR` のディレクトリごと消してください（HMAC鍵と受領ファイルも同じ場所にあり、消すとローカルで発行済みのリンクは無効になります）。

## 開発・配置・旅行発行は別操作

1. **開発**：ブランチで共通コード／IaCを変更 → `bun run check` → IaC lint → レビュー。
2. **Host配置**：dev環境へ変更セットを作成・確認・実行 → 架空データでAWS検証 → 同じコミットをprodへ配置。
3. **旅行発行**：Git外の成果物workspaceでSpec/Documentを生成・preview → 内容と期限を確認 → Publisherでデータを送信。再ビルド・再デプロイ不要。
   1. 生成：エージェントに [旅程のRecipe](docs/recipes/trip.md) と旅行の希望を渡し、Git外にJSONを1ファイル作らせる。
   2. 検査：`bun run validate <file>`（発行しない。不正な項目のパスと理由をJSONで返す。通れば承認用のSHA-256）。
   3. preview：`bun run dev` の最初の画面の「ファイルから取り込む」でファイルを選ぶ（チャットで作った場合は、その上の貼り付け欄に返事をそのまま貼る）。ファイルはブラウザ内で検査して下書きとして表示するだけで、送信しない。貼った文はHostの確認（`POST /v1/check`）へ送るが、保存はしない。
   4. 発行：`bun aws/publish.ts <file> <function> <profile> <region>` が表示するハッシュが2と同じことを確認し、末尾に付けて再実行（[AWS配置手順](aws/README.md)）。

   Switchboardが無くても、このリポジトリで動くエージェントと上のコマンドだけで一通りできる。

詳細は [開発・リリース・運用](docs/development-and-release.md)、[AWS配置手順](aws/README.md)、[旅程仕様](docs/ephemeral-trip-capsule.md)。

## 状態

Private の独立リポジトリで開発し（公開は `iunct-lab/capsule-host` に main のツリーだけ）、Issue・PR・GitHub Project で運用している。dev / prod は同じ AWS アカウントの 2 スタック（`capsule-host-dev` / `capsule-host-prod`、ap-northeast-1）。dev で `aws/verify.ts` を通したものと同じ `src` を prod にも配置し（両方の Lambda の CodeSha256 が一致する）、そのたびに配置の記録（`docs/releases.md`。Private のリポジトリだけにあり、公開のツリーには無い）へ行を足す。各環境にいま何が配置されているかは、その環境の最新の行が正。prod で動いている機能もリリース記録の prod の行が正で、主なものは、発行（操作 ID で冪等、#5）、作成者がパスキーでスマホから旅行を作る（#11）、チャットで直して反映する（#133）、予定の並べ替え（#147）、個人予定は旅程・日記は思い出で登録する入口（#494、v0.35.0）。足あと（「ここにいる」と、開いたときに自動で残す）・背景つきの足あとの地図・旅の記録（#480・#481・#563・#440・#583、v0.50.1）。2026-10-20 から、`/v1/*` は CloudFront から Lambda Web Function に OAC でつながり（API Gateway と秘密ヘッダは無い、#673）、作成者の鍵の登録・削除と旅行の受け渡し・削除には 5 分以内のサインインが要り（#748）、30 日使わない作成者の鍵は自動で消える（#744）。Switchboard の汎用成果物台帳との接続は未完成で、owner リンクは発行 CLI が入力の隣の権限 600 のファイルに保存する暫定方式のまま。
